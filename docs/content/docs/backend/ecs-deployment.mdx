## 版本与运行边界

定制版本使用自己的 Git 分支和完整提交 SHA，不使用官方镜像替代本地补丁。发布前先 fetch、rebase 并提交所有本次部署内容，在干净工作区运行 `bun scripts/verify-before-push.mjs`，通过后推送并确认 CI。不要修改已有开发工作区中的未提交文件，可在独立 worktree 中准备发布。

前端在开发机完成根路径构建，后端和独立 Agent 在 ECS 原生构建 AMD64 镜像。镜像以完整提交 SHA 标记，部署时额外记录 Docker image ID，避免移动标签造成来源混淆。国内部署优先使用可用的国内依赖镜像；镜像源故障时排查并切换可信镜像源，不借用本机代理传输大文件。

Compose 以 `docker-compose.deploy.yml` 的服务结构为基础，运行 PostgreSQL、Redis、migrate、Backend、Web 和独立 Agent。定制编排、`.env`、发行镜像引用和日志保存在仓库外的独立部署目录。使用 `CANVAS_UPDATE_POLICY=manual`，不启用指向官方发行仓库的 Host Updater。后续自有发行流程见[定制版本与更新保护](./custom-release-updates)。

小内存实例从单生成并发、单 Agent 会话开始，限制 Agent 的 Node 堆与 Redis 内存，日志设置轮转。Swap 仅作为内存不足时的缓冲，不能替代容量规划。数据库、Redis 和 Agent 不发布宿主机端口，Web 只绑定 `127.0.0.1:18880`。

## 配置迁移

迁移前对测试数据库做完整逻辑备份，并备份插件注册文件和存储加密密钥。备份和中间文件可能含凭据，目录权限使用 0700、文件使用 0600，通过 SSH 传输，不打印内容或提交到 Git。

新环境只导入模型渠道、模型能力、价格档、用户分组及其渠道关系、逻辑模型配置、平台插件启用状态和平台对象存储配置。渠道及七牛凭据采用数据库中已有的加密形式迁移，并同时迁移对应的 `.settings-key`。不导入测试用户、会话、项目、任务、账务或素材记录；正式管理员通过回环接口单独初始化。

只迁移实际使用的协议插件包，宿主随镜像重新生成内置插件。不要复制测试机的 ARM64 支付插件运行目录到 AMD64 服务器。七牛可复用已配置的私有空间和签名域名，但正式环境使用独立对象前缀，避免测试数据与正式数据混用。

顺序为：启动 PostgreSQL/Redis、执行 Schema 迁移、备份初始化后的数据库、在单个事务中导入配置、安装所需协议包及加密密钥、核对数据目录权限、启动 Agent/Backend/Web。导入失败时回滚事务，不以默认密钥或空配置继续启动。

## HTTPS 与验收

使用独立子域名，由已有宝塔 Nginx 终止 HTTPS 并代理回环入口，保留同机已有网站。DNS 生效后申请匹配域名的证书，启用自动续期及成功续期后的 Nginx 校验、重载钩子。证书申请期间只开放 ACME 校验路径，初始化完成后才开放应用入口。

明确设置 `CANVAS_CORS_ORIGINS` 和 `CANVAS_PUBLIC_BASE_URL`。两级代理都只对文本任务、Agent 事件和系统模型流式路径关闭缓冲；画布实时接口单独转发 WebSocket。访问日志不记录查询参数，避免持久化短时签名 URL。

上线检查须覆盖管理员登录/退出、未登录与跨站请求拒绝、模型目录及非付费报价、插件状态、Agent 能力接口、七牛上传/Range 读取/测试对象清理、正式素材的签名读取，以及真实页面加载。健康检查和任务生成成功都不能替代浏览器图片预览。未实际执行的付费生成、Agent 对话和 SSE 断线重连必须单独注明。

## 更新与恢复

更新前记录运行镜像的完整 SHA 和 image ID，备份数据库、持久数据、加密密钥和部署配置。等待活动任务排空后再迁移和切换镜像；保留上一版镜像及其数据库备份。恢复程序前确认数据库迁移兼容性，不能只回退镜像标签。

服务器构建缓存、源代码快照、旧镜像和备份需要设置保留策略。不要自动删除唯一的恢复点，或通过删除七牛对象释放系统盘空间。

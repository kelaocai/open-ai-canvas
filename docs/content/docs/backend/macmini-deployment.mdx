## 部署边界

镜像在开发机本地构建，通过 SSH 内网分发。前端构建参数为 `CANVAS_BASE_PATH=/rightmovie/` 与 `VITE_CANVAS_BACKEND_URL=/rightmovie/api`。默认值仍为根路径。

`docker-compose.external.yml` 复用外部 PostgreSQL 网络 `rightmovie-database`，运行独立 Redis、迁移、后端、Agent 和前端。前端仅监听本机 `127.0.0.1:18880`，共享 Nginx 将 `/rightmovie/` 去掉前缀后代理到该入口。SSE 路径需要在两级代理上关闭缓冲。现有 PostgreSQL 容器应接入这个专用网络，并建立专用账号及数据库。

## 运行目录

扩展盘上的持久根目录包含 `data/`、`redis/`、`web/`、`deployment/`。部署目录保存权限为 0600 的 `.env`、`compose.yaml`、`release.env` 和可信的 `deploy-local.py`。`.env` 配置数据库、Redis、Agent 凭证、公开访问地址和数据路径。所有真实配置都在版本库外保存。

首次管理员在尚无用户时通过注册接口创建。关闭公开注册，首次初始化通过本机回环接口完成。渠道使用系统导入导出接口转移能力和价格，再单独写入密钥。对象存储使用生产专用私有空间，上传、签名读取、浏览器预览和上游参考图读取均需验收。

## 发布流程

代码提交后运行 `bash scripts/release-macmini.sh`。脚本要求工作区干净，先运行完整推送前检查，然后构建三个 ARM64 镜像，以完整提交 SHA 标记。`RIGHTMOVIE_SSH_TARGET` 可覆盖 SSH 目标，`BUN_BIN` 可指定 Bun 可执行文件。

镜像通过 Docker save 解包为内容寻址文件，rsync 经 SSH 压缩同步到生产机的专用传输缓存。首次传输全部文件，以后复用内容相同的层文件。生产机导入镜像后，部署脚本停止入口和后端、等待任务排空，备份数据库及数据目录，执行迁移，启动服务并检查健康状态和提交号。成功后记录 `deployed-sha`，保留上一组镜像的 `previous-release.env`。

部署失败保留 `deployment-in-progress`，再次发布前需要检查日志并人工恢复。数据库结构可能变化，恢复上一版程序前需要确认迁移兼容性，必要时恢复对应数据库与数据备份。备份含敏感信息，需要额外同步到独立备份位置，并设置保留策略。保留前一版镜像以便恢复，定期检查镜像和传输缓存占用。

GitHub CI 对 main 和 PR 执行质量检查。定制仓库禁用 `Publish container images` 工作流，生产机不轮询 GitHub，也不从 GHCR 拉取业务镜像。本地发布会同步版本内的部署脚本和 Compose，生产 `.env` 与持久数据继续保留。单机更新期间会短暂中断访问。

## 公网入口与七牛预览验收

七牛自定义域名、DNS 验证、证书开通及私有鉴权的完整排查过程见[七牛私有素材预览与证书配置经验](./qiniu-private-media)。

nblink 隧道可能把 Origin 和 Referer 中的公网域名重写为本地回源地址。浏览器登录必须携带真实浏览器请求头验收。入口仅在明确的转发域名、同站 Referer 和 Fetch Metadata 满足条件时还原来源，同时对页面使用 `Referrer-Policy: same-origin`。验证正常登录成功以及跨站请求被拒绝，避免扩大后端 CORS 白名单。

七牛空间连接测试验证上传、读取及清理。S3 默认域名会强制附加 `Content-Disposition: attachment`，浏览器新标签预览需要自定义 HTTPS 访问域名。为私有空间开启每次请求的回源鉴权，在后台填写 CDN 域名并选择七牛鉴权。切换前通过实际 TLS 握手检查证书域名及有效期，确认图片返回 inline、支持 Range，并拒绝未签名和过期签名请求。切换后复核已有资源的新访问地址。

私有空间可通过七牛证书管理申请单域名证书，完成 DNS 验证后将签发的证书绑定到 CDN，并开启强制 HTTPS。免费证书到期前需要重新申请和替换，在证书管理中确认有效期及提醒设置。浏览器可能缓存旧的签名访问地址，验收时应重新获取资源访问描述。

## 部署边界

使用自己的仓库发布镜像。通过仓库变量设置前端构建前缀，例如 `CANVAS_BASE_PATH=/rightmovie/` 与 `VITE_CANVAS_BACKEND_URL=/rightmovie/api`。默认值仍为根路径。

`docker-compose.external.yml` 复用外部 PostgreSQL 网络 `rightmovie-database`，运行独立 Redis、迁移、后端、Agent 和前端。前端仅监听本机 `127.0.0.1:18880`，共享 Nginx 将 `/rightmovie/` 去掉前缀后代理到该入口。SSE 路径需要在两级代理上关闭缓冲。现有 PostgreSQL 容器应接入这个专用网络，并建立专用账号及数据库。

## 运行目录

扩展盘上的持久根目录包含 `data/`、`redis/`、`web/`、`deployment/`。部署目录保存权限为 0600 的 `.env`、`compose.yaml`、`release.env` 和可信的 `deploy-published.py`。`.env` 配置数据库、Redis、Agent 凭证、公开访问地址和数据路径。所有真实配置都在版本库外保存。

首次管理员在尚无用户时通过注册接口创建。关闭公开注册，首次初始化通过本机回环接口完成。渠道使用系统导入导出接口转移能力和价格，再单独写入密钥。对象存储使用生产专用私有空间，上传、签名读取、浏览器预览和上游参考图读取均需验收。

## 发布流程

本地检查通过后推送 main，GitHub `publish-images.yml` 运行质量检查并发布三个镜像。Mac mini 用 LaunchAgent 每五分钟运行已安装的发布脚本，只有创建 `enabled` 文件才启用自动部署。脚本只接受当前 main 提交，且该提交的发布工作流必须整体成功。

部署脚本拉取三个 SHA 标签，检查镜像 revision 并解析固定 digest。然后停止入口和后端、等待任务排空，备份数据库及数据目录，执行迁移，启动服务并检查健康状态和提交号。成功后记录 `deployed-sha`，保留上一组镜像的 `previous-release.env`。

移除 `enabled` 文件暂停后续发布。部署失败保留 `deployment-in-progress`，自动重试停止，需要检查日志后人工恢复。数据库结构可能变化，恢复上一版程序前需要确认迁移兼容性，必要时恢复对应数据库与数据备份。备份含敏感信息，需要额外同步到独立备份位置，并设置保留策略。

GitHub 公共 API 轮询无需向生产机授予仓库写权限。脚本和 Compose 的变化需要显式更新服务器安装副本；自动发布只更新镜像，不覆盖生产配置。若仓库改为私有，需要单独配置只读凭证。
